# Veer AI Editor 测试报告

日期：2026-10-19  
版本：veer-editor `main`（00f690d）加未提交的改动（输入法占位文字、实时推理、原生分段控件）

## 1. 结论

- **核心流程可用：** 导入 → 确认出口 → 对话生成修改 → 审阅 → 写入 → 撤销 / 重做 → 导出都正常。全部 126 个自动化测试通过，包括真实 Mihomo `-t` 校验和规则集地址联网检查。
- **问题清单：** 共发现 12 个问题（P1 2 个、P2 7 个、P3 3 个），没有阻断性（P0）问题。
- **最需要先修的两个：**
  - **D1：** Veer 自己添加的规则集规则无法用对话删除。
  - **D2：** 「测试」页对 `www.netflix.com` 给出了错误的「确定」结果。
- **设计评审：** 29/40（良好）。

## 4. 问题清单

| ID | 级别 | 问题 | 复现 | 期望 |
|---|---|---|---|---|
| D1 | P1 | 规则集规则无法删除 | 写入“Netflix 走日本”（RULE-SET,netflix）后说“删除 Netflix 规则”：本地解析报“只能删除明确域名的规则”；AI 计划 `remove_rule RULE-SET netflix` 报“暂不支持修改这类规则：RULE-SET” | 能删除 RULE-SET / GEOSITE / GEOIP 规则 |
| D2 | P1 | 「测试」页误报 | 写入 RULE-SET netflix 后测试 `www.netflix.com`：显示绿勾“第 10 条 → 自动选择（MATCH）”，实际运行时会先命中 netflix 规则集 → 日本出口 | 前面有无法判断的规则时，不给出绿勾结论；名称与域名相符的规则集标为“很可能命中” |
| D3 | P2 | 测试 IP 地址 | 输入 `192.168.1.5`：IP-CIDR 192.168.0.0/16 被当作“需要运行时判断”而跳过，最后落到 MATCH（复核：空输入在界面上本来就不显示结果，只是匹配函数本身会返回 MATCH，不算界面问题） | IP 输入直接匹配 IP-CIDR |
| D4 | P2 | 规则页把附加标志当成出口 | 规则页显示 “GEOIP → DIRECT,no-resolve”“IP-CIDR → DIRECT,no-resolve” | 出口显示 DIRECT，`no-resolve` 作为标签单独显示 |
| D5 | P2 | 本地解析认识的服务太少 | 目录里已有的 B站、苹果、微软、Steam、Twitter/X、Instagram、Facebook、Discord、Amazon，以及“国内网站 / 中国 IP / 局域网”、IP 与网段（10.0.0.0/8、192.168.1.1）都报“只认识常见服务” | 目录中的服务和 IP 网段都能本地解析 |
| D6 | P2 | “去掉 … 的规则”被当成否定 | “去掉 example.com 的规则”报“不支持这种否定或例外条件” | 识别为删除 |
| D7 | P2 | 城市名与繁体地区不识别 | “Netflix 走東京”变成追问 | 东京 / 東京 / 大阪 / 洛杉矶 / 首尔 / 伦敦等城市映射到地区 |
| D8 | P2 | 名称含逗号的配置无法导入 | 节点名为 “HK, Premium” 时整份配置被拒绝 | 照常导入，只是这些出口不能用于规则，并说明原因 |
| D9 | P2 | AI 请求体随节点数增长 | 3,000 节点的配置，每次发给 AI 的匿名 YAML 达 161 KB（约 5 万 token），因为节点被逐个列出 | 节点很多时按地区汇总，只列有限个，请求体控制在几十 KB 以内 |
| D10 | P3 | 禁用按钮不说明原因 | 未保存 Key 时「测试连接」「重新获取」是灰的，没有任何提示 | 悬停或旁边说明“先保存 API Key” |
| D11 | P3 | 实时推理框没有边界 | 浅色模式下推理文字直接贴在白色背景上 | 有轻微底色，与回答内容区分开 |
| D12 | P3 | 只说地区时报错 | “走日本”报“只认识常见服务” | 追问哪些流量走日本 |

**探索中确认无问题的方面：**
- **特殊配置：** YAML 锚点与合并键、缺少 `rules`、名称含引号与冒号、`include-all` / `filter` 策略组、`no-resolve` 与逻辑规则，改动后都通过 Mihomo 校验，其余内容不变。
- **规则集来源：** 6 种来源（MetaCubeX geosite / geoip、ACL4SSR、blackmatrix7、粘贴 yaml / list 地址）都通过校验。
- **大配置性能：** 600 KB（3,000 节点 / 5,000 规则）的配置，解析 0.14 s、生成并应用修改 0.82 s、差异 0.58 s、概览 0.15 s。
- **多种说法：** 中英文混写、大小写、“走 JP”、“走日本或者新加坡”（新建策略组）、“不要走香港”（排除地区）都正确。

## 6. 修复结果

12 个问题全部修复，每个都有回归测试（`Tests/VeerCoreTests/AuditFixTests.swift`）。修复后重新运行全部测试（含真实 Mihomo 校验、规则集地址联网检查和探索性用例）全部通过，截图逐项复查。

| ID | 修复 | 验证 |
|---|---|---|
| D1 | 删除计划可以指定 `RULE-SET`（规则集名称）。本地解析“删除 Netflix 规则”会找出配置中实际存在的 Netflix 规则集（包括 `Netflix`、`netflix-2` 这类命名）和 GEOSITE 规则；AI 用匿名标签“规则集1”删除时，先换回真实名称再应用。规则集定义本身保留（未被引用的规则集在 Mihomo 中合法）。系统提示补充了删除规则集的写法 | 删除后通过 Mihomo 校验；匿名标签换回真实名称 |
| D2 | 测试结果分三种：确定命中（绿色）；前面有需要运行时判断的规则（蓝色说明）；与域名同名的规则集或 GEOSITE 排在前面时，显示“很可能命中第 N 条 → 出口”（橙色），并说明规则集不含该域名时会命中哪一条 | `www.netflix.com` 显示“很可能命中第 1 条 → 日本出口” |
