# Veer AI Editor（macOS 原生重建）规格说明

> 日期：2026-10-17  
> 状态：v1 规格，作为原型设计与实现的唯一依据  
> 代码位置：`native/macos-editor/`（全新代码库，不复用 `native/macos` 与 `prototype/ai-editor` 的代码）  
> UI 原型：Open Design 项目 `Veer · AI Editor Rebuild`（见 §14）

---

## 1. 背景与重建理由

Veer 的长期目标是跨平台（macOS、Android、iOS、PC）的 AI 驱动 Mihomo 客户端。当前阶段的产品是 **隐私优先的 AI 配置编辑器**：导入 Mihomo 配置 → 用自然语言描述分流 → 审阅出口与差异 → 确认写入草稿 → 导出副本。

现有 macOS 版本（`native/macos`）是 SwiftUI 外壳 + 打包的 Node 运行时 + loopback HTTP 编辑服务。它可以工作，但：

- 应用里打包了一个 Node 运行时和 JS 依赖，体积大，启动需要拉起子进程、随机端口和会话 token。
- 编辑逻辑分散在 JS 与 Swift 两侧，状态跨进程同步，错误路径多（服务启动中、服务不可用、重启）。
- UI 经过多轮叠加修改（Liquid Glass 工作台 → Codex 式对话 → OpenCode 审阅 → Editor Studio），交互模型不统一。

本次重建：**一个进程、一种语言、一套交互模型**。编辑引擎用 Swift 重写，UI 依据新的 Open Design 原型从零实现。唯一保留的外部可执行文件是 Mihomo 校验器（`mihomo -t`），因为“YAML 可解析”不等于“Mihomo 配置有效”（`docs/MIHOMO_CORE_AGENT.md` §6.6）。

## 2. 产品定义

### 2.1 一句话

Veer AI Editor 让你用一句话修改 Mihomo 分流规则，每一处改动都先给你看清楚，再由你决定写不写。

### 2.2 目标用户

- 已经有 Mihomo / Clash Meta 配置（本地文件或订阅链接），想让某些网站或服务走指定出口的人。
- 不熟悉规则语法，或不想手写 `rule-providers`。
- 不愿意把节点地址、密码、订阅 token 交给 AI 服务。

### 2.3 核心任务（按优先级）

1. 导入配置，确认识别到了哪些出口（策略组/节点）。
2. 输入“Netflix 走日本，ChatGPT 走美国”，看到明确的“服务 → 出口”映射和规则差异。
3. 逐项接受或拒绝，写入草稿；不满意就撤销。
4. 验证某个域名现在会命中哪条规则、走哪个出口。
5. 导出完整配置副本。

### 2.4 明确不做（v1 非目标）

- 不启动 VPN、不连接 External Controller、不重载运行中的内核、不切换运行中的节点。
- 不测速、不判断节点是否可用或能否解锁某服务。看到“节点太卡了换一个”这类请求时，说明范围而不是编造数据。
- 不修改 `rules` 与新增 `rule-providers` 以外的任何字段（DNS、TUN、proxies、proxy-groups 原样保留，逐字节不变）。
- 不转换 Base64 订阅或节点 URI 列表，不合并多个配置。
- 不做云同步、账户、遥测。

## 3. 隐私与安全边界

这是产品的核心承诺，所有实现必须遵守，并在 UI 中可见、可核对。

| 数据 | 存放位置 | 是否发给 AI |
|---|---|---|
| 完整配置原文（含节点地址、密码、Provider URL） | 仅本机内存与本机会话文件 | **否** |
| 出口名称 | 本机 | **否**；发送匿名标签 `出口3（日本）` |
| 出口地区 | 本机（自动推断或用户更正） | 是，作为匿名标签的一部分 |
| 用户指令 | 本机 | 是；其中出现的真实出口名先替换为匿名标签 |
| 现有规则 | 本机 | **否** |
| 本轮之前的对话 | 本机 | 是，已匿名化的摘要（用于追问上下文） |
| API Key | macOS 钥匙串（或仅本次会话内存） | 仅作为请求头发给用户配置的 AI 服务 |
| 订阅链接 | 仅导入时使用，不持久化 | 否；会话中只记录主机名 |

要求：

- **发送内容可查看**：每轮 AI 请求都保留一份“已发送内容”，用户可在该轮展开查看实际 payload（系统提示除外的匿名出口表 + 匿名化指令 + 历史）。这是对隐私承诺的可核对证据。
- 输入框提示“请勿在指令中粘贴密钥或订阅链接”；无法保证自动识别用户自己输入的秘密，UI 不得声称“已自动脱敏一切”。
- AI 地址必须是 HTTPS，或本机 `localhost/127.0.0.1/[::1]` 的 HTTP；不得含用户名、密码、查询参数；不跟随重定向；响应上限 512 KB；超时 60 秒。
- 订阅导入只允许 HTTPS，不自动跟随重定向，上限 2 MB，只接受直接返回 YAML 的地址。
- 校验器在独立临时目录中运行，环境变量最小化，20 秒超时，输出中的秘密字段值（password/token/uuid/server/url…）替换为 `[已隐藏]`。
- 会话文件存放于 `~/Library/Application Support/Veer AI Editor/Sessions/`，权限 0600，**不包含 API Key 与订阅 URL**。
- 导出不得覆盖导入的原始文件（比较文件系统身份，包含符号链接/硬链接）；导出用原子写入。

## 4. 平台与技术栈

- macOS 26 及以上（使用原生 Liquid Glass：`glassEffect`、`GlassEffectContainer`、`.buttonStyle(.glass/.glassProminent)`）。
- Swift 6，SwiftUI 为主，必要处用 AppKit（多行输入的输入法处理、窗口快照）。
- Swift Package Manager 构建；`scripts/build-app.sh` 生成 `dist/Veer AI Editor.app`，ad-hoc 签名。
- 依赖：`Yams`（YAML 解析，libyaml）。差异算法、规则匹配、AI 客户端均自写，不引入其他依赖。
- 打包的 Mihomo 校验器：`go_core/third_party/mihomo`（Veer 本地 mirror，基于 v1.19.29）构建的 `mihomo`，用于 `-t` 配置测试。
- 简体中文为 v1 唯一界面语言；文案集中在 `Strings.swift`，不在视图中散落硬编码文本，后续可平移到 String Catalog。

## 5. 编辑引擎规格（VeerCore）

遵循 `MIHOMO_CORE_AGENT.md` §6.3 流程：自然语言 → 结构化计划 → 实体解析 → 校验 → 确定性生成 → Mihomo 语义校验 → 差异与解释 → 用户确认。

### 5.1 读取配置

- 输入为 UTF-8 文本，≤ 2 MB；顶层必须是映射。
- `proxies`、`proxy-groups`、`rules` 若存在必须是数组；`rules` 每项必须是字符串。
- 节点与策略组名称非空、唯一（含内置 `DIRECT/REJECT/REJECT-DROP/PASS/COMPATIBLE`），不得含逗号或换行（无法在规则中安全引用）。
- 策略组的 `proxies` 引用必须存在，`use` 引用的 Provider 必须存在，组嵌套无环、≤ 64 层。
- YAML 锚点展开次数上限 100。
- 产出：
  - 出口表 `targets`：策略组在前、节点在后，最后是 `DIRECT`、`REJECT`；每项 `id = target-N`、`kind = group | node | builtin`、`type`。
  - 统计：节点、策略组、规则、Provider 数。
  - 警告（不阻止编辑）：无静态出口；无 `MATCH` 兜底；`mode` 不是 `rule`。

### 5.2 计划（EditPlan v1）

与 Android/旧服务的计划格式保持兼容：

```json
{"schemaVersion":1,"operations":[
  {"kind":"rule_set","source":"metacubex-geosite","name":"netflix","targetId":"target-0"},
  {"kind":"rule_set","url":"https://raw.githubusercontent.com/...","behavior":"domain","targetId":"target-1"},
  {"kind":"route","matchType":"DOMAIN-SUFFIX","match":"example.com","targetId":"target-2"},
  {"kind":"remove_rule","matchType":"DOMAIN-SUFFIX","match":"example.com"}
]}
```

或澄清：`{"clarification":"…"}`（只能有这一个字段）。

- 1–32 个操作；只允许列出的字段，出现多余字段即拒绝。
- `matchType` 白名单：`DOMAIN, DOMAIN-SUFFIX, DOMAIN-KEYWORD, IP-CIDR, IP-CIDR6, GEOSITE, GEOIP`。
- 域名、CIDR 格式校验；同一匹配值在一个计划中不得重复或冲突（大小写不敏感）。
- `targetId` 必须存在于当前出口表。

### 5.3 规则集

| 来源 | behavior | format | URL |
|---|---|---|---|
| `metacubex-geosite` | domain | mrs | `https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/meta/geo/geosite/{name}.mrs` |
| `metacubex-geoip` | ipcidr | mrs | `…/geo/geoip/{name}.mrs`，键名 `{name}-ip` |
| `acl4ssr` | classical | text | `https://raw.githubusercontent.com/ACL4SSR/ACL4SSR/master/Clash/{name}.list` |
| `blackmatrix7` | classical | text | `https://raw.githubusercontent.com/blackmatrix7/ios_rule_script/master/rule/Clash/{name}/{name}.list` |

- 模型只给来源与名称，URL 由 Veer 构建，模型无法注入任意地址。用户粘贴的地址只接受 `raw.githubusercontent.com` / `cdn.jsdelivr.net` 的 HTTPS 文件（`.mrs/.list/.txt/.yaml/.yml`）。
- `mrs` 只支持 domain / ipcidr。
- 已有相同 URL 的 Provider 直接复用；否则使用空闲键名（冲突时加 `-veer`、`-veer2`…）。新 Provider：`type: http, behavior, format, url, path: ./rule_provider/{key}.{ext}, interval: 86400`。
- 生成预览前对新 URL 发 HEAD 请求：404 → 拒绝该计划并告诉用户去哪里找正确地址；网络失败 → 标记“未验证”，允许用户自行判断。

### 5.4 应用计划（确定性）

- 新规则插入 `rules` 顶部（优先于现有规则），保持计划中的顺序。
- `route`：删除所有相同 `类型,匹配值` 的旧规则后插入新规则；原 IP 类规则带 `no-resolve` 时保留；保留旧规则的注释。
- `remove_rule`：配置中不存在则拒绝（不静默“成功”）。
- **源码区间拼接**：只重写 `rules`（以及需要时的 `rule-providers`）这个顶层值对应的源码行区间，其余字节原样保留，包括注释、未知字段、引号风格。保持原缩进风格（是否缩进序列项）。
- 生成后重新解析并断言：① 新 `rules` 与计划预期完全一致；② 除 `rules`、`rule-providers` 外所有字段与原配置深度相等；③ 原有 Provider 未被修改。任一不满足即拒绝生成并报错。
- 产出：候选全文、逐项摘要（类型、匹配、出口、被替换的旧规则、规则集来源与验证状态）、行差异、`changed` 标志。

### 5.5 逐项接受

每个操作是一个“修改项”。用户可单独拒绝。写入时只对被接受的子集重新应用并重新校验；全部拒绝等于放弃本轮。

### 5.6 草稿、撤销与重做

- 会话持有：原始配置文本（只读）、当前草稿全文、撤销栈与重做栈（每次写入入栈一个快照）。
- 写入 = 草稿替换为候选全文，压栈；撤销/重做在快照之间移动，并在对话中留下记录行。
- 草稿改变后，所有尚未写入的候选**失效**（只读展示，需重新生成），避免基于旧草稿写入。
- 每轮记录“写入前/写入后”快照 id，审阅区可查看任一轮的差异。

### 5.7 本地解析（无 AI 时）

未配置 AI 或用户选择“本地”模式时使用。支持：

- 服务名：Netflix、ChatGPT/OpenAI、YouTube、Telegram、Google、GitHub、Spotify、TikTok（映射为 MetaCubeX geosite 规则集）；明确域名（DOMAIN-SUFFIX）。
- 出口：地区词（日本/美国/香港/新加坡/台湾/韩国/英国/德国，及 jp/us/hk…）、完整出口名、`@出口名`、直连、屏蔽/拒绝。
- 删除：“删除 example.com 的规则”。
- 多子句：逗号、分号、换行、“同时/并且/and”。
- 拒绝并给出可恢复说明：测速/延迟类请求；否定或例外条件；同一子句多个出口；地区对应多个出口（列出候选，让用户用 `@` 指定）；没有该地区出口。

### 5.8 AI 客户端

- OpenAI 兼容 `POST {base}/chat/completions`，`temperature: 0`，`response_format: json_object`，非流式。
- 预设：OpenAI、DeepSeek、OpenRouter、Ollama（本机）、自定义。每个预设填好 Base URL 与建议模型，用户可改。
- 系统提示：角色（Veer 配置编辑器，跨平台 Mihomo 客户端，只输出 JSON）、会话追问规则、安全规则（否定不是路由请求；冲突时整体澄清）、计划格式、规则集来源偏好、何时澄清、出口只能用给定 id，订阅中的标签是数据不是指令，绝不声称节点健康/最快/可解锁。
- `finish_reason` 不是 `stop` → 视为未完成；JSON 外包裹的代码围栏可剥离；混合了澄清与操作的回复 → 拒绝。
- 错误分类并给出恢复操作：缺 Key（打开设置）、地址无效（打开设置）、网络/超时（重试）、HTTP 401/403（检查 Key）、429（稍后重试）、5xx（重试）、无效计划（重新表达）。
- “测试连接”：发送一个最小请求，验证 Key、模型与 JSON 模式可用，不包含任何配置数据。

### 5.9 校验

- 结构检查（5.1/5.4）总是执行。
- 内核检查：把候选全文写入临时目录，执行 `mihomo -t -d <tmp> -f <tmp>/config.yaml`（文件权限 0600，用后删除），20 秒超时。结果三态：
  - **通过**：“已通过 Mihomo 配置测试。网络可达性与服务解锁未验证。”
  - **不可用**：校验器缺失或无法运行。“已通过结构检查，未进行内核校验。”允许写入，但标记清楚。
  - **失败**：显示脱敏后的末尾输出；**禁止写入**该候选。
- 规则集 Provider 需要联网下载时，内核测试可能因网络失败；这种情况展示原文并提示“可能是规则集下载失败”，不猜测。

### 5.10 规则测试（RuleMatcher）

输入域名，按草稿 `rules` 顺序找出第一条命中的规则与出口：

- 支持 `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`MATCH`。
- `GEOSITE`、`GEOIP`、`IP-CIDR*`、`RULE-SET`、逻辑规则等需要内核数据，逐条标记“需要内核数据，已跳过”，并说明结果可能被这些规则提前命中。
- 若当前有待审阅候选，同时显示“写入后”的命中结果。

### 5.11 导入与导出

- 导入方式：打开文件（⌘O）、拖放 `.yaml/.yml`、粘贴 YAML 文本（⌘⇧V）、订阅/配置 HTTPS 链接、示例配置（离线演示，明确标注“示例”）。
- 导入后先显示**出口确认**：识别到的出口及推断地区，标出“未指定地区”的数量；用户可更正地区或直接开始。地区标签是“声明/推断，未实测”。
- 导出：保存面板（⌘E），默认文件名 `原名-veer.yaml`；导出前显示本次相对原始配置的增删条数；可选“导出前进行内核校验”。拒绝覆盖原文件。导出成功后会话的“未导出修改”计数清零。

### 5.12 会话

- 每次导入成为一个会话：标题（文件名或订阅主机名）、来源、导入时间、原文、草稿、对话、撤销栈、出口地区更正。
- 侧栏列出会话，支持搜索、重命名、删除（需确认）。有未导出修改的会话显示标记（圆点 + 无障碍文本“有未导出修改”）。
- 退出或删除有未导出修改的会话时提示。会话可恢复：重新打开应用回到上次会话；中断中的 AI 请求恢复为“已取消”。

## 6. 信息架构与界面

### 6.1 窗口结构

```text
┌───────────┬──────────────────────────────────┬──────────────┐
│ 侧栏       │ 主区：对话                         │ 检查器（可收起）│
│ · 新建导入 │ 顶栏：会话标题 · 草稿状态 · 工具     │ 变更 规则      │
│ · 会话列表 │ 消息流（单列居中，最大阅读宽度）     │ 测试 出口      │
│ · 设置入口 │ 底部：输入框（@ 出口，/ 命令）      │               │
└───────────┴──────────────────────────────────┴──────────────┘
```

- `NavigationSplitView`（侧栏 + 详情）+ 详情右侧的 `inspector`。
- 默认窗口 1320 × 860，最小 960 × 640。宽度不足时检查器以覆盖层方式出现，不挤压对话到不可读。
- 窗口工具栏（原生）：侧栏开关、会话标题与副标题（`草稿 · 3 项未导出修改` / `与原始配置一致`）、撤销、重做、导出、检查器开关。不在内容区重复标题条。

### 6.2 开始页（无会话或新建）

- 中央：Veer 标识、一句话说明、主要操作“导入配置文件”（玻璃突出按钮），次要操作“粘贴 YAML”“订阅链接”“试用示例配置”。
- 整个区域是拖放目标，拖入时显示放置提示。
- 底部隐私说明：“配置在本机解析。AI 只收到匿名出口与你的指令。”
- 订阅链接以 sheet 输入，显示导入中、失败（原因 + 重试）。

### 6.3 出口确认（导入后、首次对话前）

- 卡片式列表：出口名称（可截断，悬停显示全名）、类型（策略组/节点）、地区下拉（推断值或“未指定”）。
- 摘要：`识别到 12 个出口 · 3 个未指定地区`；警告（无 MATCH、mode 非 rule）以内联提示显示。
- 主要操作“开始编辑”；次要“稍后再说”。之后可在检查器“出口”标签修改。

### 6.4 对话

- 用户消息：右侧短气泡。
- 助手回合（左对齐，同一阅读轨道，不层层套卡片）：
  1. **处理步骤**（真实任务状态，不是模型推理）：理解指令 → 检查出口 → 生成修改 → 校验。每步状态：进行中 / 完成 / 失败 / 已取消。运行中可取消（⌘.）。完成后折叠为“处理完成 · 4 步 · 2.4 秒”，可展开。
  2. **结果摘要**一句话：“准备了 2 项分流修改，等待你确认。”
  3. **修改项列表**：每项一行，`Netflix → 日本出口（日本·推断）`，副行 `规则集 metacubex/geosite/netflix · 已验证地址` 或 `DOMAIN-SUFFIX,example.com`；被替换的旧规则以“替换：…”显示。每项一个接受/拒绝开关（默认接受）。
  4. **校验结果**：三态徽标（图标 + 文字，不只靠颜色）。
  5. **操作**：主要“写入草稿”（玻璃突出，⌘↩），次要“放弃”。写入后变为“已写入草稿 · 撤销”。旧回合只读，按钮替换为状态文本（已写入/已放弃/已失效）。
  6. 辅助链接：“查看差异”（打开检查器“变更”并定位到本轮）、“查看发送给 AI 的内容”。
- **澄清**：助手的问题以普通段落呈现，附快捷回复（例如列出可选出口），不是错误样式。
- **超出范围**（测速、切换节点、启动 VPN）：说明范围与可以做什么，不是红色错误。
- **错误**：说明发生了什么 + 恢复操作（重试 / 打开设置 / 改用本地解析）。
- 滚动：新内容自动跟随到底；用户上翻时停止跟随，显示“回到最新”。

### 6.5 输入框

- 自动增高（1–8 行），⌘↩ 或 ↩ 发送（⇧↩ 换行）；输入法组字期间回车不发送。
- `@` 弹出出口补全（名称 + 地区 + 类型），选中后插入 `@出口名`，解析时视为精确出口。
- `/` 弹出命令：`/test 域名`（规则测试）、`/undo`、`/export`、`/rules`。
- 左下：解析模式切换“AI · 模型名”/“本地解析”；未配置 AI 时显示“本地解析 · 配置 AI”。右下：发送按钮（玻璃突出；生成中变为停止）。
- 占位文字：`描述分流，例如“Netflix 走日本，ChatGPT 走美国”`；下方细字：`请勿粘贴密钥或订阅链接`。
- 空对话时，在消息区显示 3–4 个示例指令芯片。

### 6.6 检查器

- **变更**：所选回合（默认最近一轮）的统一差异视图。等宽字体，行号，`+`/`−` 前缀 + 低饱和底色（颜色不是唯一线索），未改动区域折叠为“… 42 行未改动”。顶部可切换“本轮候选 / 相对原始配置”。
- **规则**：草稿 `rules` 全表，序号、类型、匹配值、出口；顶部筛选框（⌘F）；本次会话新增的行有“新增”标记；`RULE-SET` 行可展开显示 Provider URL。
- **测试**：域名输入 + 结果：命中规则（序号、原文）、出口；跳过的规则数及原因；若有候选，显示“写入后”对比。
- **出口**：出口列表，编辑地区；“地区为声明或推断，未实测”。

### 6.7 设置（⌘,）

- **AI**：服务预设、Base URL、模型、API Key（安全输入框，保存在钥匙串 / 仅本次会话），“测试连接”及结果；已保存时只显示“已保存到钥匙串”，不回填。
- **隐私**：解释发送内容；“对话中显示发送内容入口”开关；“清除所有本地会话”。
- **校验**：内置 Mihomo 版本、状态（可用/不可用）、“导出前默认校验”开关。

## 7. 页面状态覆盖

| 场景 | 状态 |
|---|---|
| 开始页 | 空、拖放悬停、导入中、导入失败（YAML 错误行/超限/非映射/重名/逗号名称/循环引用）、订阅失败（非 HTTPS、重定向、超限、网络） |
| 出口确认 | 正常、有未指定地区、无静态出口（警告）、长名称、2500 个出口（滚动） |
| 对话 | 空（示例芯片）、生成中（可取消）、已取消、待审阅、部分拒绝、全部拒绝、已写入、已撤销、已失效、无需修改、澄清、超出范围、AI 错误（分类恢复）、校验失败（禁写）、校验器不可用（可写、标注） |
| 输入框 | 正常、禁用（生成中）、未配置 AI（本地模式）、@ 补全无匹配 |
| 检查器 | 无变更、长规则、筛选无结果、测试无命中（落到 MATCH / 无 MATCH）、测试跳过内核规则 |
| 设置 | 未配置、已保存、测试中、测试成功、测试失败 |
| 全局 | 浅色、深色、减少透明度（玻璃降级为实底）、减少动效、增强对比度、窄窗口 |

## 8. 视觉设计系统（macOS）

沿用 `AGENTS.md` 的原则（清晰、安静、可靠、轻量、不炫技），换成 macOS 的实现方式。

- **颜色**：系统语义色（`.primary/.secondary/.tertiary`、`windowBackground`、`controlBackground`、`separator`）。品牌强调色：Veer 绿（浅色 `#1F9D55` 系、深色提亮一档），只用于主要操作、选中、已写入状态等小面积。状态色语义固定：通过=绿、警告/未验证=琥珀、失败=红、信息=蓝；状态永远“图标 + 文字”。
- **字体**：系统字体（SF Pro）+ 等宽（SF Mono）。层级：窗口标题由工具栏承担；`title2` 用于开始页标题；`headline` 用于区块标题；`body` 正文；`callout/subheadline` 次要；`caption` 标签；规则与差异用 `.monospaced` 的 `body/callout`。单屏不超过 4 个明显层级。
- **间距**（4 点网格）：`xxs 2, xs 4, sm 8, md 12, lg 16, xl 24, xxl 32, xxxl 48`。对话阅读轨道最大宽度 760。
- **圆角**：`small 6`（徽标、代码行高亮）、`medium 10`（输入框、修改项行）、`large 16`（面板、输入框外框）、`pill`（芯片）。
- **层级**：靠底色明度差与 1 px 分隔线；不用阴影堆叠；正文、规则、差异一律实底。
- **Liquid Glass 只在操作层**：主要按钮（导入、写入草稿、发送）、输入框外框、浮动的“回到最新”、toast。减少透明度时自动降级为实底（系统行为 + 自绘部分手动处理）。
- **动效**：150–250 ms 状态切换；处理步骤展开、修改项出现用轻微淡入；不弹跳、不无限闪烁；减少动效时取消。
- **图标**：SF Symbols，统一线性风格、统一尺寸。

## 10. 无障碍

- 所有控件 VoiceOver 标签；状态徽标朗读文字；修改项朗读“Netflix 到 日本出口，已接受”。
- 处理步骤状态变化与写入/撤销结果通过无障碍通知播报。
- 键盘可达：Tab 顺序合理，修改项开关可用空格切换。
- 点击目标 ≥ 28 pt（macOS 控件标准），主要按钮使用 `.large` 控件尺寸。
- 支持动态字体以外的系统设置：增强对比度、减少透明度、减少动效。

## 11. 性能目标

- 冷启动到可交互 < 1 秒（无子进程启动）。
- 2 MB / 2000 条规则的配置：导入解析 < 300 ms，应用计划与差异 < 200 ms（不含网络与内核校验）。
- 规则表、差异视图使用惰性列表，滚动保持流畅。

## 12. 测试与验收

### 12.1 单元测试（VeerCore）

- 配置读取：各类无效输入的错误信息；出口表顺序与 id；警告。
- 计划校验：多余字段、非法类型、重复匹配、未知出口、澄清混合。
- 应用：插入顺序、替换旧规则、保留 no-resolve、删除不存在拒绝、**非 rules 字段逐字节保留**（含注释、流式序列、缩进与非缩进序列）、规则集复用与命名冲突、mrs+classical 拒绝。
- 本地解析：示例指令、多子句、地区歧义、否定、测速请求。
- 匿名化：出口名替换、最长优先、发送内容不含原始名称/服务器/密码。
- 差异：增删改、空文本、大文本。
- 规则测试：各类型命中与跳过。
- 校验器：通过/失败/不可用，输出脱敏。
- 会话存储：往返、不含 Key 与订阅 URL、文件权限 0600。

### 12.2 应用层测试

- 状态机：生成 → 待审阅 → 部分拒绝 → 写入 → 撤销 → 重做；草稿变化使候选失效；旧回合只读。
- AI 客户端用本地假服务覆盖错误分类。

### 12.3 视觉验收

- 运行应用并截图：开始页、出口确认、待审阅回合、已写入回合、检查器四个标签、设置、错误态；浅色与深色；默认与最小窗口。
- 与 Open Design 原型逐屏对照：信息层级、对齐、间距、状态完整性。

### 12.4 验收清单

- [ ] 应用不包含 Node 运行时，不监听任何端口。
- [ ] 导入示例配置 → “Netflix 走日本，ChatGPT 走美国”（本地解析）→ 2 项修改 → 写入 → 撤销 → 重做 → 导出，导出文件除 rules/rule-providers 外与原文逐字节一致。
- [ ] 发送给 AI 的内容中不含原始出口名、服务器地址、密码与原规则。
- [ ] 校验失败的候选无法写入。
- [ ] 浅色 / 深色截图通过审查。
- [ ] 全部单元测试通过，Release 构建与签名校验通过。

## 15. 实现记录（2026-10-17）

### 已完成

- `native/macos-editor`：VeerCore（引擎）+ VeerEditorApp（SwiftUI），`scripts/build-app.sh` 生成 ad-hoc 签名的 `dist/Veer AI Editor.app`。
- Open Design 原型：`prototype/editor-rebuild/veer-editor.html`。

### 与规格的偏差

| 规格 | 实现 | 原因 |
|---|---|---|
| 校验器从 stdin 读配置 | 写入 0600 临时文件后 `-f` 指定 | 不依赖 `-f -` 的平台行为；目录在校验后删除 |
| 内容区修改项作为一组列表 | 每项独立卡片 | 采纳 Open Design 原型 |
| 失效候选写入状态 | “失效”由草稿是否等于候选的基线推导，不存储 | 撤销回到基线后候选重新可写，避免永久失效 |
| 差异算法 Myers | patience（唯一行锚点）+ Myers 处理间隙 | 新增多个 rule-provider 时，重复的 `type: http` 行不会错位对齐 |
| 构建 | 默认 `MacOSX26.5.sdk` | macOS 27 SDK 的 `@State` 宏插件只随 Xcode 提供 |

### 实现中发现并修复的问题

- 切换接受开关后立即写入，会写入上一次的候选（重新校验尚未完成）。现在重新校验期间禁止写入，并显示“正在按你的选择重新生成并校验…”。
- 撤销后，被撤销的回合仍显示“已写入草稿”。现在显示“已撤销 · 重做”，重做后恢复。

### 未验证

- 真实订阅链接导入、钥匙串读写（测试使用内存实现）。
- VoiceOver 朗读、输入法组字下的回车行为、减少透明度/增强对比度下的实际外观。
